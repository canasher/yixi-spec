> 状态：已有工程约束的汇总；业务目标与待接入能力按条目标明。  
> 适用：`yixi-spec`、`yixi-saas`、`yixi-web` 的业务协作。  
> 依据：2026-10-01 [仓库核对记录](../业务/租洗/资料来源/仓库核对记录.md)。实施前复核目标仓库当前约定，不将历史核对视为最新运行状态。

## 三个仓库如何分工

| 仓库 | 管理的内容 | 与其他仓库如何关联 |
|---|---|---|
| [yixi-spec](https://github.com/canasher/yixi-spec) | 业务需求、规则、领域目标、任务、验收预期和业务决策 | 用稳定编号及文档提交为开发切片固定依据 |
| [yixi-saas](https://github.com/canasher/yixi-saas) | 后端实现、实际 API、数据库迁移、后端测试与工程 ADR | 提交引用 FR/BR/TASK/UAT；实际接口与变更证据回链至规范 |
| [yixi-web](https://github.com/canasher/yixi-web) | 前端应用、domain、生成 Client、页面和前端测试 | 根据正式 OpenAPI 接入同一事实，回链文档版本及接口版本 |

代码仓库当前的 `AGENTS.md` 和已接受 ADR 是各自工程约束的主版。本文件集中保存跨业务必须理解的边界；业务细节仍由对应业务目录管理，不能另造一套权限、库存或资金权威。

## 后端、数据与身份边界

Java21、Spring Boot3.3家族、模块化单体、经典三层；业务放modules/business，不增加DDD/Microservice框架。Controller接DTO返回VO，Facade编排，Service独占自己Mapper。system与business不互依；业务需要身份/文件/导出时使用platform稳定端口和app装配，不能为方便直接引入实现模块。

平台库存储企业准入/账号/资源及既有文件、导出任务基础；租洗资产、单据、库存、配额、客户资金和费用在企业库。企业由服务端Session/设备授权/受控Job恢复，factory固定合法INITIAL；所有上下文finally清理。HTTP登录链路与企业切库由既有IAM提供，不把companyCode客户端值当可信路由。

当前`LoginSessionType`只有PLATFORM、COMPANY、IMPLEMENTATION；安全路由把`/manager/**`、`/device/**`、`/app/**`限定为企业/实施Session。酒店外部用户和独立设备主体属于待接入能力，不能把租洗设计中的HOTEL业务主体当作现有枚举，也不能仅凭`terminalCode`完成设备认证。有人操作的生产/物流端复用合法企业员工身份并校验任务范围；酒店账号复用Account凭据能力，由[TASK-02](../业务/租洗/共用规范/实施计划.md#TASK-02)补受限客户绑定与Session契约；无人设备由同任务明确可信主体、凭据、撤销及业务范围。新增路由必须显式纳入安全规则，不能靠路径名称或`/open/**`放行来接通。

实时命令和RFID/库存/配额/资金可用值固定WRITE。已开始事务不切数据源；历史报表明确可接受延迟时才@ReadReplica。冻结/删除文件涉及平台库，不能包在企业业务事务里假装原子；租洗接入见[文件与导出边界](../业务/租洗/共用规范/领域与技术设计.md#MODEL-FILES)。

## 前端与接口边界

前端沿 `apps → domains → packages`，业务 core 不依赖 UI 框架；页面通过显式 manifest 接入，业务 HTTP 使用正式 OpenAPI 生成的 Client。具体四端载体、Session/缓存隔离、字段格式和接口交付链集中维护在[租洗前端架构](../业务/租洗/共用规范/领域与技术设计.md#ARCH-WEB)及[接口契约](../业务/租洗/共用规范/领域与技术设计.md#ARCH-CONTRACT)。全局入口不再复制这些实施条款。
