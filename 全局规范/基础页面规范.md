# 基础页面规范

> 日期：2026-10-11；交互补充：2026-10-17、2026-10-18。适用于超管和客户中台的 PC 管理列表及其详情、编辑入口。
> 依据：现有超管企业列表和前端开发护栏。本次按用户要求整理并用于租洗原型调整；业务规则和已经确认的页面内容继续按各业务主版执行。
> 返回：[首页](../README.md) · [系统边界](系统边界与共用约定.md)。

## 入口和菜单怎样保持一致

首页快捷入口、应用目录和左侧菜单进入同一项业务时，使用同一个已接入页面；菜单名称、面包屑末级和页面对象一致。首页应能直接找到当前主要业务，不让用户先进入旧占位页，再返回目录寻找已经可用的功能。

仍需保留的旧版预览要明确标注范围，并提供当前已接入页面的去向；不能把“功能正在筹备中”当作现有业务的默认入口。入口调整继续沿用原权限和应用接入关系，不通过隐藏菜单或新增直达链接改变访问资格。

## 页面先统一成什么样

以超管的“企业列表”为参照。打开一个列表，用户从上往下应该依次看到：查什么、能做什么、查到了什么、还有多少条。

```text
导航：当前位置

┌ 筛选区 ──────────────────────────────────────────┐
│ 客户 [请选择]   状态 [全部]   日期 [请选择]         │
│                              查询  重置  更多条件 │
└──────────────────────────────────────────────────┘

┌ 数据区 ──────────────────────────────────────────┐
│ 新增  导出  其他业务操作        刷新  行距  显示列 │
│──────────────────────────────────────────────────│
│ 表头                                             │
│ 数据                                             │
│                                                  │
│                       共 36 条  ‹ 1 2 3 4 › 10条/页│
└──────────────────────────────────────────────────┘
```

上图说明分区和阅读顺序，按钮是否与条件在同一行由可用宽度决定。导航已经说明页面名称，表格上方不要再放一个重复的大标题。演示提示放在筛选区上方，不混进表格工具栏。

## 筛选条件怎么放

- 常用条件默认显示，通常不超过三个。条件多时，把不常用的收进“更多条件”，不要让用户一进来先看半屏输入框。
- 同一行的标签、输入框和按钮对齐。输入框撑满自己的位置，不能有的下拉框很短、有的把旁边按钮挤走。标签用“客户”“状态”“业务日期”这样的短名称。
- “查询”在前，“重置”在后；有更多条件时再接“更多条件”。按钮放在筛选区右侧，屏幕窄了允许整组换到下一行，不拆得七零八落。
- 输入条件后点“查询”，按提交的条件更新结果，并回到第一页。输入框里尚未查询的内容，不影响当前列表和导出范围。简单的状态切换如采用“选完即查”，须整页一致，不能同一组条件一半立即查询、一半等按钮。
- 收起更多条件不会取消已经选好的条件。按钮显示“更多条件（2）”，让用户知道仍有两个条件在生效。
- “重置”同时清空可见和收起的条件，回到第一页；保留当前页面类别和每页条数。例如“品项分类”页不能因重置跳成“品项”页。
- 日期要说明是业务日期还是记录时间；占位文字用“全部状态”“名称或编码”，不重复标签，也不放研发用词。

## 表格和按钮怎么放

业务按钮在左，刷新、行距、显示列等表格工具在右。业务按钮多时自然换行，工具组保持完整；不要挤到表格外。最主要的操作使用主按钮，其余按钮保持普通样式。

表格工具即使只有图标，也要在鼠标移上去时说明用途，并能通过键盘操作。调整显示列不能隐藏必要的操作入口，也不能改变导出范围或权限。

列宽要给名称、金额、状态和操作留足位置。长编号能完整查看，长说明可换行或通过详情查看。列太多就在表格内部左右滚动，整张页面不要跟着横向滚动；右侧固定操作列不能把按钮截掉。不要为了塞进一屏，把字号缩小或把每一列挤成两三个字。

长表头按完整词组换行；同一表头中的并列金额口径可以在分隔符后换行，不能把词组逐字拆成竖列，也不能截去部分口径。有数据时仍保留原列宽、表内横滚和固定操作，不能用缩窄数据列或隐藏内容换取表头整齐。

详情中的关联表确实没有记录时，保留必要表头和空态，不因固定宽列产生多余的横向滚动条；有记录且列超出容器时仍保留表内左右滚动，不能通过统一隐藏横向溢出来截断内容。

列表只提供该业务本来就需要的操作。不能为了看起来统一，给账单、资金流水等页面硬加删除按钮。按钮名称说明实际动作，例如“新增客户”“核准账单”，避免只写“处理”。

## 分页怎么做

分页放在表格下方靠右，包含总条数、页码和每页条数。普通管理列表默认每页 10 条，可选 10、20、50、100 条。逐件资产、库存列表可保留每页 20 件的现有默认，并显示“共多少件”。

- 翻页保留当前筛选；更换每页条数回到第一页。
- 打开详情再关闭，仍回到原来的筛选、页码和每页条数。刷新页面也能恢复这些已提交的查询状态。
- 数据减少导致原页码不存在时，显示最后一个有效页；没有匹配结果时保留筛选并明确提示无记录，分页可以隐藏，方便用户重新查。
- 分页表达的是当前筛选结果。导出全部结果时不能只导出当前一页；跨页勾选按该业务已有规则处理。
- 抽屉里的简短明细、配额矩阵、扫描任务等按各自使用方式分页，不强行套用主列表的每页条数。

## 详情和编辑怎么打开

常规详情、编辑从右侧抽屉打开。标题说明对象和动作，例如“编辑客户”。保存、取消或关闭固定在底部居中；内容很长时只滚动内容区，滚到底仍能找到按钮。

字段多的宽抽屉用两列，小屏改为一列；窄抽屉直接用一列。不要因为电脑屏幕大，就在同一个抽屉里突然变成三四列。长说明、原因、明细表独占一行，标签宽度保持一致。

保存失败要保留输入，并指出哪里需要处理。涉及钱、责任或危险操作时，保留业务原有的确认步骤；不能用一次普通“保存”替代原来的核准、复核或结果查询。一次性密码等专用弹窗仍使用自己的确认方式。

已经修改且尚未保存的表单，在点击关闭、取消、遮罩、按 Esc 或切换页面前，提示“内容尚未保存”，提供“继续编辑”和“放弃修改”。继续编辑保留全部输入及校验提示，明确放弃才关闭；未修改的只读详情可以直接关闭。浏览器刷新或离开站点采用可用的离开提醒；不承诺浏览器强制关闭后仍能恢复本地未保存内容。

提交中的表单防止重复提交；结果尚未确定时继续保留原操作查询入口，不能通过关闭、重新打开或更换操作号把同一次动作重新执行。只有确认原操作没有产生效果，或者开始一项新的业务动作，才生成新操作。已提交结果的恢复与尚未提交的输入保护是两件事，不共用“重新开始”按钮。

## 字段和金额怎样输入

同屏列表筛选、抽屉和弹窗可以出现同名字段，但每个表单控件必须有唯一标识，并与自己的可见标签对应。点击标签应聚焦正确控件；键盘和读屏能区分当前字段，必填、错误和帮助说明关联到同一控件。不要依靠占位文字代替标签，也不要把组件内部的重复标识带到整张页面。

金额字段明确标注币种及单位。允许输入 `100`、`100.5` 或 `100.50`，在失焦或提交前按同一规则显示为 `100.00`、`100.50`；编辑过程中保留可继续输入的小数，不因尚未输入末位就清空。空值、零和缺价分别处理。超出业务允许精度、范围、负号或非数字时指出问题，不静默截断或四舍五入用户输入来通过校验。传给现有业务命令的值仍使用精确到分的十进制字符串，真实可用金额由原业务规则重新校验。

纯技术防重键由程序生成并保存，用户填写的是金额、凭证和原因，不需要自行编写内部操作号。已有外部业务来源时，继续以明确命名的凭证编号按原规则形成来源键，并保留原去重范围；不能拼入客户、金额、次数或新前缀来绕过既有来源唯一约束。原操作号可供查询与授权诊断，重试、关闭后恢复及页面刷新不能换号重做；相同键不同内容继续按原幂等规则拒绝。业务凭证编号与技术操作号分开命名。

## 没有数据、出错时怎么说

| 情况 | 页面表达 |
|---|---|
| 正在读取 | 显示加载状态，避免用户把上一批结果误当成本次结果 |
| 确实没有记录 | “暂无客户记录”等，并在用户有权限时保留新增入口 |
| 条件没有匹配结果 | “没有符合条件的客户”，保留查询和重置 |
| 读取失败 | “暂时无法读取，请重试”，不能显示为“暂无数据” |
| 没有权限 | 说明无法查看或操作，不能把受限内容当空记录 |
| 当前环境可读但不能保存 | 进入页面即明确“当前仅可查看，不能保存”，说明已知的存储访问或运行环境问题及处理方式；已有内容仍可查看，保存继续受实际能力和业务校验限制 |
| 租洗原型采用页面内保存队列 | 进入页面即提示“当前为单标签页演示，请只保留一个页面进行修改。演示数据保存在当前浏览器。”；允许在当前页保存，不承诺多个标签页同时修改受保护 |
| 保存失败 | 保留输入，说明失败原因和可执行的下一步 |
| 还不能确定是否成功 | 提供查询原操作结果的入口，避免用户重复付款、退款或交付 |

演示页面依赖本机能力时，应在用户开始填写前提示已知限制，并按当前实际使用的保存模式说明；不能因缺少一项可替代能力就笼统要求升级浏览器。进入业务写入前已明确拒绝的操作，不能显示成成功或“结果未知”；真正的未知结果仍查询原操作。提前提示不替代提交时的校验，不通过清空数据来解除限制。

租洗前端原型按2026-10-18用户[已接受的演示方案](../维护记录/2026-10-18发布环境复验记录.md#DEMO-PAGE-QUEUE)保留现有 `localStorage` 的存储键、数据格式及账号/企业/工厂作用域。浏览器提供 `Web Locks` 时继续使用原锁；缺少该能力但本机存储可用时，使用当前页面内按原存储键串行执行的保存队列。队列只负责本页动作次序，不新增持久化层或后端，不把它当作跨标签页互斥；同一浏览器来源内的其他标签页仍可能访问同一份数据，不能同时修改。单标签页提示是使用限制，不表示系统已检测并自动禁用其他标签页。

每次保存轮到执行后重新读取现有快照，继续执行原操作号、幂等、版本与业务校验。原生锁请求或业务动作失败不能改走另一条路径自动重做；一个失败动作不能阻塞本页后续保存，错误仍须按原语义展示并保留输入。成功数据仍由原 `localStorage` 写入并在同一来源刷新后读取，排队中及未保存的输入不因此获得刷新恢复保证。此调整只适用于合成数据原型演示，不替代正式业务的服务端事务、权限及并发要求。

具体业务结果仍以[共用交互要求](../业务/租洗/共用规范/产品需求.md#UI-COMMON)为准，这里只规定页面怎样表达。

## 产品怎么检查

拿企业列表和待检查页面并排看，按下面几步操作即可：

1. 先看布局：筛选在上，业务按钮在左，工具在右，分页在表格下面；没有重复的大标题。
2. 填几个条件再查询，翻到第二页，打开并关闭详情，确认条件和页码还在。
3. 选择每页 20 条，确认回到第一页；重置后所有条件清空，每页条数还保留。
4. 展开更多条件，选一个再收起，确认有数量提示；点重置，确认隐藏条件也清空。
5. 查一个不存在的名称，确认显示空结果；模拟读取或保存失败，确认不是假成功，也不丢输入。
6. 把浏览器宽度分别调到 1280、1080、1440 像素。检查长客户名、长编号、按钮换行、表格横向滚动；打开抽屉、切换页签并滚到底，确认内容和底部按钮都能看到。
7. 从首页快捷入口、目录和左侧菜单进入同一功能，确认到达同一已接入页面；旧版预览能够找到正确去向，菜单、面包屑和页面对象一致。
8. 修改一项尚未保存的内容，分别用关闭、取消、遮罩、Esc 和页面内跳转离开；选择继续编辑后输入仍在，明确放弃后才退出。另核对保存失败和结果待确认时能否恢复原动作。
9. 同时打开含有同名字段的筛选区和编辑面板，逐一点击标签、使用键盘，确认操作的是对应控件；金额分别输入整数、一位小数、空值和超精度值，确认显示友好且业务约束不变。

生产扫描、物流现场操作和酒店手机页面另按各端要求设计。它们需要适合触摸、扫描和现场确认，不能为了统一外观照搬 PC 表格。

## 给研发的尺寸参考和维护位置

| 项目 | 默认做法 |
|---|---|
| 筛选区 | 白底，圆角 6px，内边距上下 22px、左右 24px；标签宽度保持一致 |
| 筛选排列 | 桌面按四列组织，三组常用条件加一组按钮；1180px 及以下两列，760px 及以下一列；长标签和控件不得溢出 |
| 分区间距 | 筛选区与数据区间隔 12px；字段纵向间隔 14px、横向间隔 24px |
| 数据区 | 白底，圆角 6px，内边距上下 16px、左右 24px；工具栏至少 48px 高 |
| 分页 | 下方靠右，允许在较窄宽度下换行；随表格内容排列，不悬浮遮挡最后一行 |
| 抽屉 | 按内容选择宽度，最大不超过视口；一列或两列由抽屉实际可用宽度决定 |

布局基准来自 [EnterpriseListPage.tsx](https://github.com/canasher/yixi-web/blob/e4096b173015c72f4afc6b87a78f21c369d0420f/apps/platform-admin/src/pages/enterprises/EnterpriseListPage.tsx) 及同版本的 [开发护栏](https://github.com/canasher/yixi-web/blob/e4096b173015c72f4afc6b87a78f21c369d0420f/docs/DEVELOPMENT_GUARDRAILS.md)。尺寸是默认参考，特殊页面应写明原因并实际检查，不能只凭 CSS 数值宣称符合。
