# 人工确认与升级

> 流程约定 1.0；目标是少问、问到关键，不是让人补齐每个技术细节。
> 返回：[流程首页](README.md) · 业务调查：[业务确认工作手册](../协作指南/业务确认工作手册.md)。

## 人的最小职责

AI 负责查资料、比方案、拆任务、写代码、执行检查和汇总证据。人提供系统中没有的现场事实，采纳业务结果和必要架构变更，授权外部影响/生产操作，并按风险确认验收。产品可以组织调查而不独自承担经营授权；一个人可兼角色，但必须注明以什么权限确认。

不要求每个普通 PR 人工逐行读代码。已经明确授权的技术范围由 AI 连续执行，不能每次重新问相同问题；“客户什么时候恢复配额”“是否启用自动赔偿”等则不能以技术裁量替代。

## 提问前先做的工作

先读主版、PD、已有采纳、[待确认总表](../维护记录/待确认事项.md)、相关工作手册与目标代码。把问题分成事实缺失、业务选择、技术选择、执行权限和环境障碍。能通过读取查明的自行查明；缺样机不是产品不懂业务，缺测试环境也不应变成要求产品设计架构。

十四类问题沿原编号管理。AI 为当前切片筛选关联问题并预填已知信息，不新建一份重复清单。只阻断受影响动作；可以记录“已解决部分，余项受阻”，不因一条未来需求未定关闭全部开发。

## 最小决策卡

| 字段 | AI 先填写 |
|---|---|
| 决定什么 | 一个明确问题；关联原问题、PD/BR/TASK，不让人从零设计 |
| 已知与未知 | 已读依据、当前推荐、缺失现场事实；不能把设计设想写成真实证据 |
| 选择与后果 | 推荐及前提、可行替代，对正常/异常结果、历史事实、范围及风险的影响 |
| 需要谁确认 | 具体授权角色；未知人员注明待指定，不代签 |
| 确认范围 | 客户/协议、品项、版本、生效时点、例外；选择方案不等于批准所有参数 |
| 未回复时 | 哪些动作保持禁用/模拟，哪些工作继续；不采用沉默批准 |
| 回写与验证 | 采纳记录位置、需同步主版/索引和正常/异常预期 |

把相关问题集中成小批次，优先提出当前关键路径上最少的问题。收到回复后核对是否回答了实际阻塞；完整时自动记录与同步，不再重复询问。回复范围模糊且会改变经营结果时再缩小确认，不替人补全承诺。

## 配额恢复示例：避免一个“选 A”批准过多事情

依据当前推荐，可让人选择司机有效交接释放或工厂实收释放；但应同时注明首客的交接证据是否已核实、具体协议覆盖范围和旧轮次快照。配额选择不同时批准物流损失责任、无限增配、退款或产权改变。

司机交接 80 件、工厂收到 78 件的合成场景，分别询问差异 2 件的调查和处置，不把“司机恢复”推导成“酒店不承担任何责任”，也不把“工厂恢复”推导成“酒店自动赔 2 件”。具体问题沿[问题-03讨论卡](../协作指南/业务确认工作手册.md#Q-03)。

确认充分后，AI 回写决策/规则及关联任务、UAT 和 JSON；然后重新判断该切片门禁。新规则不会使历史轮次自动变更，已有真实记录按正式更正规则处理。

## 升级、停止与恢复

发现越权、不可恢复数据风险、疑似敏感信息暴露、无依据收费/退款或安全隔离冲突时，停止相应动作，保留最少且去敏的证据。不要为了追求自治先操作再通知。

普通问题达到重试或任务预算时，报告已经尝试什么、失败在哪、推荐下一步及最小需要。恢复时重新确认授权与基线仍适用；一次确认可覆盖明确的一组动作，但不能无限期扩大到新客户、新环境或更高风险行为。
