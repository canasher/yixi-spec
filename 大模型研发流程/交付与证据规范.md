# 交付与证据规范

> 流程约定 1.0；一份执行记录贯穿任务，不增加平行的业务规则台账。
> 返回：[流程首页](README.md) · [记录模板](模板/任务执行记录.json) · [检查器](../校验/检查执行记录.py)。

## 每个切片的最小交付

交付摘要必须回答：做了什么、没做什么、依据哪个规范/规则版本、改了哪些仓库和提交、实际验证了什么、仍有哪些风险/未知、是否提交/合入/部署/商业启用，以及下一条安全动作。没有审查到的问题写“本轮未发现”，不写“风险为零”。

| 信息 | 最小记录 |
|---|---|
| 目标与范围 | 原 TASK/FR/BR/PD/UAT 或文档任务依据，执行授权，允许路径，排除动作 |
| 输入与输出版本 | 各仓完整输入 SHA、实际候选 SHA、接口/迁移/终端版本（适用时） |
| 决策与阻塞 | 原问题号、采纳依据、待定范围、可继续部分；不把推荐改写为已批准 |
| 验证 | 每项操作/命令、环境、候选版本、时间、结果、退出码或业务预期、证据位置 |
| 审查 | 实际审查者/代理、审查版本、发现及处置、独立性与覆盖限制 |
| 恢复 | 已完成、未完成、失败尝试、当前工作区、下一动作、不可重复的副作用 |

原始日志和视频等放代码 PR/CI 制品或受控存储，规范仓只放去敏摘要与可追溯索引；不能把凭据、客户原始资料和完整生产日志随报告提交。证据设置保留方式，易过期制品需记录归档位置或失效风险。

## 结构化记录的使用范围

模板中的 `is_template=true` 和空值是刻意保留，不是就绪记录。复制到当次受控位置后，由 AI 填实际值并设为 false；模板本身不填假提交、授权人或通过结果。短任务可先用同字段的 Markdown 记录，需机器检查时导出一次 JSON；不要求人手填 JSON。

`kind` 区分 DOCUMENTATION、ENGINEERING、BUSINESS；按实际差异判断，不能把业务变更标成文档任务来减免检查。`mode` 对应调查/隔离模拟/正式实现，沿[启动协议](任务启动协议.md)。`baselines` 是输入版本，`candidates` 是被验证的输出版本；每个允许修改的仓库都需记录基线。

`rule_decisions` 只引用已有采纳，不复制公式。正式业务实现要求规则集版本和全部适用采纳；`blockers` 说明阻断 SIMULATION、IMPLEMENTATION 或 VERIFY 的哪种动作。用减少声明项来隐藏实际依赖会违反本流程，检查器不能替代完整影响分析。

`allowed_paths` 使用 `owner/repo:相对文件或目录/` 的具体前缀，不支持通配符或越出仓库的路径；例如只允许规范工作时使用 `canasher/yixi-spec:大模型研发流程/`，实际改其他路径须如实补齐授权范围。

以下是数组元素格式示意，不是已执行记录；证据仍须实际取得：

```json
{
  "rule_decision_example": {"id": "PD-023", "status": "PENDING", "evidence_ref": null},
  "blocker_example": {"summary": "恢复节点尚待采纳", "blocks": ["IMPLEMENTATION"], "status": "OPEN", "resolution_ref": null},
  "check_example": {
    "id": "backend-integration", "status": "NOT_RUN", "repository": "canasher/yixi-saas",
    "commit": null, "command": null, "environment": null, "executed_at": null,
    "exit_code": null, "evidence_ref": null, "reason": "待核对实际命令与环境"
  }
}
```

`required_checks` 是编码前确定的必需检查 ID。`checks` 中每项包含 ID、状态、仓库、候选提交、命令、环境、执行时间、退出码及证据引用。自定义人工操作的原始记录可另附；本检查器验证的是自动命令记录。它不执行输入命令，不从字符串中推导权限。

执行方式：

```bash
# 检查模板结构；不代表任何真实任务可开工
python3 -B 校验/检查执行记录.py 大模型研发流程/模板/任务执行记录.json
# 对实际记录检查开工/验证声明；路径示例需要替换
python3 -B 校验/检查执行记录.py /受控位置/本次执行记录.json --gate start
python3 -B 校验/检查执行记录.py /受控位置/本次执行记录.json --gate verify
# 用内存合成正反例检查检查器自身
python3 -B 校验/检查执行记录.py --self-test
```

模板通过结构检查，但应被 start/verify 拒绝。即使实际记录的 verify 返回成功，也只说明声明自洽，**不证明链接内容、提交存在、授权真实性、检查覆盖充分或日志未伪造**；还需读取实际证据和适用 CI。检查器不判定人工验收、合入许可、发布或商业启用。

## 人看到的摘要模板

```text
目标/范围：
规范及规则版本：
实际变更/提交：
验证：通过项；失败项；未执行项及原因；证据位置。
审查：谁审查、发现与限制。
状态：已提交？已合入？目标环境验收？已部署？商业启用？分别填写。
待人决定：只列当前必要决定；没有则写本轮无新增决定请求。
剩余风险/下一动作：
```

## 复盘以减少返工为目标

记录首轮验证是否通过、返工原因、重复故障、人工介入是否本可由读取解决、证据缺失和恢复是否成功。每次只把高频且可验证的问题改进为测试、规则或工具约束；不要为了报表制造大量度量字段，也不以提交数/代码行数评价 AI 产出。
