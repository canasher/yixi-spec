# 任务启动协议

> 流程约定 1.0；AI 是主要执行者，人不必逐步拆任务。
> 返回：[流程首页](README.md) · 下一步：[自主决策边界](自主决策边界.md)。

## 目标输入与默认行为

输入可以是一个业务目标或现有 TASK。AI 先从仓库读取可得信息，能自行查明的不重复询问；不把模糊目标理解为整期实现、生产操作或任意跨仓修改许可。首次输出简短说明目标、修改范围、验证方式；随后在范围内连续工作，不每一步等待确认。

开始前完成以下核对，并将结果写入当次执行记录，而不是另造一份 PRD：

| 检查 | 必须取得的结果 |
|---|---|
| 操作授权 | 用户要求、允许仓库/路径、允许读写/提交/发布的动作；不明确的高风险动作不做 |
| 工作区 | 分支、完整提交、已有修改和未跟踪文件；不得覆盖他人工作；有重叠先隔离或协调 |
| 业务上下文 | 首页、目标模块、全部相关 FR/BR/PD、TASK 依赖与 UAT；正文和 JSON 对照，不只读标题 |
| 规则状态 | 已采纳的记录与适用范围，未采纳项及实际阻断动作；不得仅凭枚举或空表认定就绪 |
| 工程约束 | 目标仓库当前 AGENTS、已接受 ADR、实际调用链、接口/迁移/权限和旧业务替换影响 |
| 验证条件 | 实际可用构建与测试命令、隔离数据、服务、设备、证据存储；缺失项明确列出 |

规范版本按[基线管理](规范与代码基线.md)固定。找不到目标或引用失效先搜索与核对，仍无法定位再一次性说明缺口；不可猜一个编号继续。

## 三种执行模式

| 模式 | 允许事项 | 不能据此宣称 |
|---|---|---|
| DISCOVER：调查 | 只读核对；在授权范围整理草案、提出方案、准备测试设计 | 正式实现已开始、规则已采纳 |
| SIMULATION：隔离验证 | 使用合成数据验证明确标注的假设；不接生产、不触发真实资金/通知/设备动作 | 正式策略已批准、真实 UAT 或真机已通过 |
| IMPLEMENTATION：正式实现 | 依已采纳规则和当前工程约束构建可验收切片 | 自动获得合入、发布、客户责任或商业启用授权 |

未定商业参数可以不阻断已确定的基础能力或受控模拟；但会影响业务结果的公式、状态流转没有定论时，不能把任意选项写成生产默认。把切片拆到无阻塞部分，再按[人工升级](人工确认与升级.md)提交最小问题。

## AI 如何拆分并推进

优先交付一个能验证业务结果的纵向切片：必要后端模型与接口、前端接入、对应测试及文档一起完成；不把 TASK-18 当作所有后端结束后的前端总包。纯规范或纯工程任务可声明前端不适用并说明理由。

拆解由 AI 执行：找依赖 → 确定最小范围 → 识别接口生产方和使用方 → 定义先失败后通过的验证 → 编码与修复。既有 TASK 是需求追踪单位，子切片不重编原编号，也不能因为完成其中一部分就关闭整张任务。

项目负责人无需回答类名、方法拆分等已授权细节。新增框架、改变多租户/鉴权边界、破坏性迁移或扩大一期范围等不能混入普通实现，按[边界矩阵](自主决策边界.md)办理。

## 可直接交给 AI 的入口指令

```text
按 yixi-spec 的大模型研发流程处理指定 TASK 或业务目标。
先读取当前规范与目标代码仓库，固定基线并识别授权范围。
自主拆分、实施和验证无阻塞的切片；已有信息自行检索，不逐步请示。
对未批准规则给出依据、推荐和最小确认问题，同时推进不依赖它的部分。
提交权限按本次授权执行；不擅自合入、发布、变更权限或启用商业行为。
结束时交付代码/文档版本、实际验证证据、未完成项和可续做记录。
```

这条指令不会赋予工具中不存在的能力。没有代码运行环境、浏览器或样机就记录限制，不能用“按流程要求”推导为已执行。
