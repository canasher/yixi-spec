# 租洗一期产品确认清单

这份文档用来一起看原型、讨论业务怎么做、记下还没定的事。产品可以先看这里，需要细节时再看文末的链接。

整理日期：2026-10-11；入口和交互说明补充：2026-10-17。部分页面要求已经确认，也已经有演示页面；还没定的主要是具体客户怎么用、现场怎么做，以及收费和责任约定。本文分别写清楚，不要求把已定内容重新确认。示例中的酒店、件数和金额都是为了方便讨论。

返回：[仓库首页](../README.md) · [租洗业务总览](../业务/租洗/README.md)

## 先说清楚这次做什么

一期做租洗：洗涤厂把布草租给酒店使用，收回后清洗，再送出去。这里的“布草”指床单、被套、毛巾等。

| 已定的方向 | 具体意思 |
|---|---|
| 先做租洗，普洗以后做 | 酒店把自己的布草单独交给工厂清洗，属于后续讨论的普洗业务 |
| 一期使用电子标签识别每件布草 | 扫描后能知道是哪一件，现场用哪些机器还要确定 |
| 一期包括四类使用场景 | 工厂电脑、生产现场、司机作业、酒店手机查询；并非只做电脑页面 |

自动下单、酒店在线下单和付款、酒店签收按钮、电脑端完整报表、采购商城等，当前安排在后续。看原型时提出的新想法先记下来，再决定哪期做。完整说明见[后续范围](../业务/租洗/后续范围.md)。

**当前已经提交了一批可操作的演示页面，使用的是演示数据，还没连上正式业务，也没完成现场试用检查。** 页面上能点、能保存，不代表真实收货、扣款或退款已经能用。

## 这些页面要求已经定了

2026-10-01 的[页面确认记录](../业务/租洗/共用规范/决策记录.md#R11-UI)已经确定了下面这些要求。看原型时，重点检查有没有做到、是否好用；不需要再问一次“要不要做”。

| 页面 | 已经确定要这样做 | 还需要补什么 |
|---|---|---|
| 客户和线路的作业配置 | 看得出当前采用哪项设置、设置从哪里来；保存草稿和正式启用分开；新设置不直接改掉已执行的记录 | 首批客户需要哪些交接证明、扫描要求是多少 |
| 发货单和配送 | 订购、备货、装车、实交、差额分别显示；少送后能查退回、补发或取消；能返回原单查看经过 | 谁能批准取消、交接用什么证明、何时允许自动确认 |
| 租赁配置数 | 分清合同约定数量、临时增加数量、待发占用、未释放占用和可新增数量；超配时另行提示，能查占用来自哪张单 | 每家酒店约定多少、按司机交接还是工厂实收恢复可领数量 |
| 客户账单 | 每笔费用能找到来源；原金额、调整和未付金额分开；已确认的账保留原记录，后续修改另留记录 | 收费时间、实际价格、税和账期 |
| 客户账户和退款 | 分清已退、正在退、还能退；显示退到哪里、是否完成；结果没确定时查原退款，避免重复退 | 哪些客户可用赠送或赊账、额度多少、哪些费用可用赠送 |
| 赔偿和找回 | 能找到原案件和布草；减免多少、减掉多少欠款、实际退多少钱分别显示 | 赔偿价格、减免比例、布草归谁、哪些情况允许自动处理 |

筛选、查看详情、返回列表保留筛选和页码，以及显示操作人、时间、修改前后内容，也已有[页面要求](../业务/租洗/共用规范/产品需求.md#UI-COMMON)。适用页面若缺少这些内容，应记为需要补齐。

本次现场审查后，用户已要求调整入口、未保存内容保护和信息层级。看页面时再检查：快捷入口是否进入当前租洗页面；修改后关闭是否允许继续编辑；金额能否直接输入整数或一位小数；发货先看摘要和待办，生产物流先看任务进度；超配时是否清楚显示“可新增数量0件”和超配多少。详细要求见[基础页面规范](../全局规范/基础页面规范.md)；实际改动和检查范围见[2026-10-17调整记录](../维护记录/2026-10-17原型交互调整记录.md)。

补送如何接着原单处理、退款如何分清欠款和已付款、赔偿减免如何分配，也已有[文档方案](../业务/租洗/共用规范/决策记录.md#DECISION-ADOPTION)。后面的例子是帮助理解这些方案。真正给某家客户使用时，仍要补齐合同、金额和负责人同意的范围。

“页面要求已经定了”不表示每个按钮的位置和提示文字都不能改。看原型发现不好用，可以直接提修改；页面已经做出来，也不自动代表所有业务约定都已同意。

## 看原型时，从哪里开始

演示地址：待填写，由负责演示的同事提供。登录后从“应用目录”进入“租洗客户与服务”等已接入的租洗应用；首页当前租洗快捷入口应进入同一业务。旧版“洗涤订单／全部订单”的占位预览不作为本轮租洗原型入口。下面按业务顺序查看；菜单和面包屑应与实际页面一致。

| 要看什么 | 去哪里 | 试着做什么、看什么 |
|---|---|---|
| 酒店订了哪些服务、还能领多少 | 租洗客户与服务 → 客户列表、服务明细、租赁配置数 | 找一家演示酒店，看看布草种类、规格、服务时间和可新增数量是否好理解；超配数量与可新增数量分开 |
| 布草有多少、在哪里 | 租洗资产与库存 → 布草信息、期初导入、库存查询 | 找一件布草，看看能否分清厂里、车上和酒店里的布草 |
| 订货、备货、送货 | 租洗订单与配送 → 发货单；租洗物流管理 → 配送任务、租赁备货、装车、送达 | 从一张发货单往下看，分清订了多少、装了多少、实际交了多少 |
| 收回了多少 | 租洗订单与配送 → 收货单 | 查看司机收的数量和工厂实际收到的数量，看看差了几件、能否找到原因 |
| 洗好、返洗和报废 | 租洗生产作业 → 租赁打扎、返洗、报废 | 看看哪些布草可以发出，没洗好或损坏的怎么处理 |
| 盘点和赔偿 | 租洗资产与库存 → 盘点记录；租洗质量与处置 → 丢失赔偿、丢失回购 | 看少件怎样登记，找回后能否查到原来的赔偿记录 |
| 收费和退款 | 租洗报价与财务 → 客户报价单、客户账单、客户账户、资金记录 | 找一笔费用，看得出为什么收、收了多少、退了多少、还有多少在处理吗 |

这些入口按本轮规范与前端基线核对。2026-10-11 整理时只核对了页面代码；2026-10-17 已在用户指定浏览器对可访问的演示页面作现场审查，确认入口与未保存表单问题。修改后的实际回归及未覆盖页面另记本轮调整记录，不能把审查或演示操作视为正式业务验收。

看页面时，遇到问题写一句具体的话就够了。例如：“发货单里看得到少了两件，但找不到补送入口。”尽量带上页面名和刚才做的操作。

## 还需要补充的现场做法和客户约定

下面按场景说明已有方案和仍缺的信息。标明“页面已定”或“文档已有方案”的部分，先按现有要求检查；需要讨论的是每项留下的具体问题。先看近期要用到的部分，不清楚就写“不清楚，找谁了解”，不用一次填完。产品负责把问题说清楚；现场人员提供实际做法；涉及钱和责任时，请财务和有权决定的人一起确认。

<a id="CUSTOMER"></a>
### 1. 一家酒店开通后，谁能看、谁能操作？

比如，酒店前台要查收发数量，店长要看费用，同一个人可能负责两家酒店。

要定：谁开账号？每个人能看哪些酒店，能不能看价格、欠费和下载单据？员工离职或换店后，谁负责取消权限？司机是只能看自己负责的任务，还是确实需要看其他任务？

建议先列出实际岗位和要做的事。给大家都开全部权限，虽然省事，也会让不该看到的人看到客户或账目。

请产品、酒店联系人和运营一起填，具体账号怎么实现交给研发。参考[原问题的详细说明](业务确认工作手册.md#Q-02)。

<a id="OPENING"></a>
### 2. 开始使用系统时，原来那批布草和余额怎么算？

酒店已经拿着一批布草，工厂仓库也有存货，账户里还有原来的余额。这些都需要有依据地登记进去。页面里的“期初导入”，就是登记开始使用系统时已有的东西和钱。

要定：谁提供数量和余额，谁核对？不知道以前洗了几次时怎么记录？现有干净布草由谁检查后允许发出，需要留下什么证明？

现有建议是：登记成功后，另行检查能不能发货。有检查记录的干净布草，经有权限的人确认后才发出；没有依据的数量、洗涤次数和余额不猜填。这样准备工作多一步，但能减少一开始就记错账或发错货。

请仓管、实施人员和财务一起填，准备现有盘点单、交接单和余额记录。参考[原问题的详细说明](业务确认工作手册.md#Q-04)。

<a id="DELIVERY"></a>
### 3. 订了 100 件，只收到 98 件，剩下两件怎么办？

**页面已定：** 实交 98 件、还有两件没处理，要分别显示；退回、补发、取消要能找到原来的记录。

要分清两件事：酒店还要不要这两件，以及这两件现在在哪里。可能还在车上、已经退回工厂，也可能暂时找不到。

| 选择 | 后续要做什么 |
|---|---|
| 酒店仍然需要，安排补送 | 记录还差两件；处理原来两件的去向；补送时能找到原单，避免重复收费 |
| 酒店不要了，取消剩余数量 | 由有权限的人确认取消；另外处理实物去向、费用和可能的退款 |

文档已有方案是先保留补送需求，取消需要明确批准。两种处理方式都已有设计，不用重新决定是否提供；还要补充的是谁能批准取消，以及实际发生少送时怎样跟酒店确认。不能只改成“已完成”，把两件的下落和钱一起略过去。

还要定：酒店没人确认时，凭什么算送到了？现有建议是保留人工交接证明，超时先提醒。若希望到时间自动算完成，需要说清依据、酒店提出异议的期限，以及由谁处理争议。

请产品、物流负责人和酒店联系人一起填。参考[交接说明](业务确认工作手册.md#Q-05)。

<a id="RETURN"></a>
### 4. 酒店把布草交给司机后，什么时候能再领？

**页面已定：** 要显示可新增数量，也能查出哪些订单和未收回的布草占了数量。已经超配时保留超配事实，可新增数量显示0。下面要确定的是客户采用哪种恢复时间。

假设酒店最多可以领 100 件，已经全部领出，没有其他待发订单。司机收回了 80 件，工厂清点后只收到 78 件，另外两件待查。

| 选择 | 酒店什么时候能再领 | 需要考虑什么 |
|---|---|---|
| 司机有交接证明就恢复可领数量 | 司机交接后可以再领 80 件；返厂时不会再加 78 件 | 酒店等得少，但必须能证明司机接到了哪些布草；少的两件还要查 |
| 工厂收到后再恢复可领数量 | 司机交接后暂不恢复；工厂确认后可以再领 78 件 | 数量按实际到厂确认，但酒店可能要等车辆回厂 |

现有建议是通常按司机交接，需要更严格管理的客户按工厂实收。请确认首批客户采用哪一种、交接证明是什么，以及少的两件由谁调查。不能只凭差了两件就让酒店赔钱。

还要说清：司机漏扫、同一件扫了两次、甲酒店的布草在乙酒店收回时，现场交给谁处理。参考[完整例子和待查事项](业务确认工作手册.md#Q-03)，请运营、司机、仓管和酒店联系人一起填。

<a id="QUALITY"></a>
### 5. 洗完以后，谁说可以再发？没洗好怎么算？

比如，洗了 100 件，其中 90 件合格，10 件需要重洗。要能分清哪些可以发、哪些还要处理。

要定：谁检查，检查什么，要留什么记录？打成一扎是否还需要确认已经检查合格？返洗和特殊清洗，哪些情况向客户收费、哪些由工厂承担？

现有建议是把“打成一扎”和“检查后允许发货”分开；重洗次数和是否收费也分别记录。一次打印标签不能算洗了一次，人工确认也不能写成机器检测合格。

请生产负责人说明现场检查方法，涉及收费时请财务一起确认。参考[放行说明](业务确认工作手册.md#Q-04)和[返洗、损坏说明](业务确认工作手册.md#Q-09)。

<a id="BILLING"></a>
### 6. 从什么时候开始算钱，少送了怎么改？

**页面已定：** 费用能查到原单；原价格和后续调整分开保留，不能用新价格直接覆盖旧单。

拿首批客户的一份合同和价目表来讨论：下单就记费用，还是送到后再记？先付款才能备货，还是按约定账期结算？价格是否含税？新价格从哪天开始适用？

现有建议是订单确认时记费用，实际交付有差异时另作调整，并保留当时的价格。这个收费时间还需要业务和财务确认。

请至少算清三笔：正常送货、少送后补送、取消剩余数量。例子里如果约定最终每件收 2 元，订 100 件就是 200 元；少送两件后是继续补送，还是减掉 4 元，取决于[第 3 项](#DELIVERY)确定的处理方式。2 元只是演示价格。

请财务和业务负责人写明收费时间、价格、税、账期，以及每笔例子最后该收多少钱。参考[计费说明](业务确认工作手册.md#Q-06)。

<a id="REFUND"></a>
### 7. 充值的钱、赠送的钱、赊账，退款时怎么分？

**页面已定：** 退款要显示各部分的金额、去向和处理情况，不能只给一个总数。

比如，一笔 100 元费用，用了充值余额 60 元、赠送金额 20 元、赊账 20 元。取消后不能把这 100 元都当现金退给客户。

文档已有方案是：赠送金额不换成现金；赊账没还的，先减欠款；已经还过的，按原来的还款来源处理。每一部分分别显示，才看得清客户实际拿回了什么。这里说明已写好的处理办法；具体客户的使用资格和额度还要确认。

要定：哪些客户可以用赠送和赊账？扣款先用哪一种？赠送可用于哪些费用？允许欠多少、超过后谁能批准？请财务分别算一笔混合付款和一笔已还部分欠款的退款。

看页面时检查：“已退”和“正在退”是否清楚；第一次退款还没结果时，能否查询原来的处理情况，避免再退一次。这些展示和操作要求已经定了。参考[资金和退款说明](业务确认工作手册.md#Q-07)。

<a id="LOSS"></a>
### 8. 盘点少了、布草破了，什么时候找客户赔？

盘点少 10 件，可能还在车上，也可能放错地方或漏扫。破损也可能是正常磨损、工厂操作损坏或客户使用不当。

现有建议是先登记问题、查原因，再认定责任。报废意味着不能继续使用，不能因此直接得出“客户应该赔钱”。

要定：多久没回来需要提醒，什么时候开始查找？谁查、看什么证明、谁能决定赔偿或免赔？仓库确实一件都没有时，谁确认这个结果？

请仓管和运营各带一个真实例子，金额和责任由有权决定的人确认。参考[异常和责任说明](业务确认工作手册.md#Q-09)。

<a id="FOUND"></a>
### 9. 已经赔过的布草又找到了，退多少、归谁？

**页面已定：** 找回记录要关联原赔偿单；减免、减少欠款和退款分别显示，退款没成功时不能写成已到账。

页面里的“丢失回购”，需要在这里说清楚。找回布草以后，要分别处理减免赔偿、退款和布草归谁。

文档已有处理方案：先检查找回的布草，再按合同决定减免多少钱；先减掉还欠的赔偿，再退已经付过的钱。找回或退款，都不自动决定布草归谁。还要确认的是客户合同中的金额、比例、归属和允许自动处理的情况。

举例：应赔 100 元，客户已付 40 元、还欠 60 元。如果合同允许减免 80 元，按上述方案，先减掉欠款 60 元，再退 20 元。**这只是说明怎么算钱，80 元并非建议的赔偿标准。**

请业务负责人和财务确认：按什么金额算减免、比例多少、如何处理零头、布草归谁；什么情况可以自动处理，什么情况必须找人审核。不要只填“退 80%”，还要写清是哪个金额的 80%。参考[赔偿后找回说明](业务确认工作手册.md#Q-08)。

### 10. 夜里收的货算哪天？昨天的账出错了怎么改？

**页面已定：** 已确认的账保留原记录，修改另留调整记录。下面要确定的是工厂怎样划分一天，以及谁负责确认迟到的数据。

比如，23:58 收货，00:05 才联网传上来。要明确这笔算哪天，以及用什么证明实际收货时间。

现有建议是按工厂约定的业务日期统计；晚传的数据可以补进报告，已经确认的账用调整记录说明原因，保留原记录。这样能查清“当时看到什么、后来为什么变了”。

请运营和财务写明一天从几点到几点、晚传怎么处理、谁能确认修改。司机收回数和工厂复核数是不同步骤，不能相加当成收回总数。参考[日期和报表说明](业务确认工作手册.md#Q-11)。

## 讨论结果写在这里

每次选一个问题，复制下面这张表填写即可。若只是改按钮、列名或页面布局，在“结论”里直接写改成什么；涉及业务做法，再把下面几项写全。

| 要记什么 | 填写内容 |
|---|---|
| 讨论哪个问题、哪个页面 | 待填写 |
| 结论 | 采用文中建议／另有做法（写清楚）／还没定 |
| 实际怎么做 | 谁操作、做什么、完成后数量或金额怎样变化 |
| 哪些客户适用、从什么时候开始 | 待填写；是否影响之前的订单也写清楚 |
| 有哪些例外 | 例如少收、取消、重复操作时怎么办 |
| 按这个办法算一笔 | 写下开始数量或金额、操作过程、最后结果 |
| 谁确认、哪天确认 | 姓名和日期；涉及钱和责任时，由有权决定的人确认 |
| 还缺什么、谁去了解、什么时候回来讨论 | 没定的部分保留在这里 |
| 正式说明改在哪里 | 文档维护人补链接，产品不用填写技术编号 |

已有页面确认继续有效，本次没有新增业务确认结论。后续只记录新补充或变更的决定，由文档维护人更新到对应业务说明，再补上链接。只确认某个问题，就只对这个问题生效；确认页面好用，也不等于同意其中所有收费做法。
