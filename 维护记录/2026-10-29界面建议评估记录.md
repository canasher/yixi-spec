## 十条建议的评估

以下保留最初建议评估。用户认可效果图后，适合的原则已按本记录后文写入基础页面规范；不代表批准全量换色、组件迁移或无关页面重构，长期规则仍只在该主版维护。

| 原建议 | 对易洗的判断与适用方式 |
|---|---|
| 1. 不用中点分隔文案 | 可作为新改界面文案的偏好，优先用布局、间距和明确标签区分信息。优先级低，不据此批量改规范导航、来源原件或业务数据。 |
| 2. 不加冗余解释 | 高价值，现有规范已有要求。删除重复标题和自我介绍式说明；正常录入简短提示，异常按需展开原因。必要状态、单位和风险反馈继续可见。 |
| 3. 文案符合目标用户 | 高价值，使用录单员、仓管和财务能识别的中文业务名称及具体动作，不在默认界面展示内部枚举、服务内部 ID 或校验公式。 |
| 4. 颜色全部换 Radix | 建议先统一语义变量，再按需映射成熟色阶；保持成功、警告、危险等既有含义。暂不建议全量换色，不由使用颜色库推导更换组件库。 |
| 5. 对齐与嵌套圆角 | 对齐优先。品项与本次数量相邻固定，数值、金额右对齐并保留单位；嵌套圆角按间距协调，不能为了外观挤窄输入、遮挡末行。 |
| 6. 统一 0.5px 边框 | 不建议作为硬规则。输入框、焦点、错误和选中状态先保证可辨认；细分隔线仅在实际设备和缩放条件下验证后使用。 |
| 7. 少动效，ease-out 250ms | 采纳减少干扰的方向；时长和曲线作为按组件调整的参考。高频录入、焦点移动和提交反馈不等待装饰动画，尊重减少动态效果的设置。 |
| 8. 三至四档字号，最低 12px | 采纳字号层级收敛，不把 12px 当普遍可读性保证。建议正文和关键表格优先 14–16px，12px 仅用于辅助内容；这是项目建议，需结合设备和缩放检查。 |
| 9. 减少不必要判断 | 价值最高。当前未选协议且仅有一个有效协议时自动带出，展开有效品项并支持连续录数；多协议、清空已填数量、未保存离页及有业务后果的确认继续保留。 |
| 10. 少装饰圆角、阴影和彩条 | 采用统一、克制的层级，延续现有尺寸基准。浮层可用阴影表示层级，风险状态有文字或图标，不用纯装饰彩条抢占录单注意力。 |

数量口径中的需求、已交付、在途和待发各有独立标签；需求、履约、支付和账单审核不合并。未知结果继续查询原操作，合成数据、本机保存与实际适用的单标签页限制在开始操作前可见。

技术依据：[Radix 色阶用途](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale)、[W3C 非文本对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast)、[字体与可读性说明](https://www.section508.gov/develop/fonts-typography/)、[减少动态效果实践](https://www.w3.org/WAI/WCAG22/Techniques/css/C39.html)。资料用于解释建议边界，不作为易洗页面已经符合可访问性要求的证据。
