## 四、登录、应用入口与模拟数据

### 请求与会话边界

| 场景 | 处理要求 |
|---|---|
| 现有账号登录、退出、会话恢复 | 沿用现有认证流程，正常管理原有会话；不复制第二套认证逻辑 |

| 应用主页及模块导航 | 保留当前视觉与操作路径；现有预览目录继续如实标明性质，不冒充企业开通结果 |
| 租洗原型查询、保存、审核、资金和状态操作 | 在显式的演示上下文中使用模拟数据；未模拟的业务操作明确失败，不转发真实业务后端 |
| 演示角色和异常切换 | 只改变演示视角或模拟结果，不增授真实权限、不伪造真实身份 |

当前用户需具备现有客户中台及入口访问条件。遇到缺失权限或应用准入时，先核对当前实现及账户范围，登记具体阻塞，不以全放行或伪造权限快照解决。

“现有账号登录”指客户中台。酒店 H5 仍为独立受限演示上下文，不能把企业员工会话当作正式酒店身份；打开酒店或终端演示路径时不在 URL 中传递真实凭据。

### 同一电脑内共享状态

1. 同一演示场景使用统一的客户、协议、品项、资产与单据标识，列表、详情、关联页面和各端查询从一致的模拟事实读取结果。
2. 核心操作后，相关端别通过约定的刷新或重新查询看到同一结果。四端分别预置相似静态数据不计为共享状态验证通过。
3. 不同端口属于不同浏览器来源，不能假定各自的内存或 `localStorage` 天然共享。首批调查需明确状态归属、跨入口读写方式及恢复策略，并在两个相关入口间实际验证。
4. 优先利用现有工程和依赖实现最小方案；需要新增服务、依赖或调整受限配置时，先给出具体方案及授权需求。本计划不预先指定新框架或通用模拟引擎。
5. 演示状态与正式登录缓存分开管理。切换企业、用户或重新进入场景时，不得将上一上下文的数据带入新上下文；重置演示数据不清除正式账号、权限或业务数据。
6. 提供统一重置入口，并在首批交付中明确刷新是否保留进度、哪些入口共享状态及适用浏览器条件。多设备实时同步不作为本轮验收项。

## 五、视觉与交互标准

以当前客户中台导航、应用主页、表格和抽屉为基线，复用现有组件和样式。实施时查看实际页面并保留不含敏感信息的对照证据；已交付切片的浏览器与截图检查见执行记录，未交付页面仍须逐页核对，不能由局部结果推导全量视觉验收通过。

- 保持现有字体、字号、配色、间距、边框、图标、表格密度和反馈方式；不另建主题或重新设计应用主页。
- 查询区、常用／高级条件、列设置、分页、右侧抽屉及底部操作区沿用现有模式；只为本次页面补必要样式。
- 移动与触控页面沿用相同视觉语言，按现有移动组件适配触控尺寸和窄屏布局，不直接压缩 PC 表格代替移动交互。
- 页面及演示导航显著标明“模拟数据 / 原型演示”；正常操作文案面向业务人员，技术追踪编号放在文档或适当诊断位置。
- 保存改变模拟事实及关联视图；取消不生效；校验失败和版本冲突保留输入；已生效事实按规范使用受控更正。
- 支持返回保留必要筛选与页码、详情直接进入及刷新恢复，区分加载、空数据、失败、无权限、结果未知和部分完成。

字段类型沿用[正式契约约定](../业务/租洗/共用规范/领域与技术设计.md#ARCH-CONTRACT)：Long ID、关联 ID 和不透明 `version` 使用十进制字符串，数量与分页保持数值，金额按约定使用十进制字符串。缺失正式契约时使用明确标识的原型类型并登记缺口，不手写不存在的业务 HTTP operation，不修改生成代码。

## 八、核心链路与演示场景

主链按[客户与服务](../业务/租洗/客户与服务/README.md)、[资产与库存](../业务/租洗/资产与库存/README.md)、[订单与配送](../业务/租洗/订单与配送/README.md)、[收货与日单](../业务/租洗/收货与日单/README.md)及[酒店查询与报表](../业务/租洗/酒店查询与报表/README.md)的适用规则细化。

以下步骤是最终跨端目标。PC 优先阶段用显式模拟场景驱动终端事件、验证 PC 状态和关联查询，后续再由实际终端／酒店页面替换这些演示操作并执行跨端回归。

1. 登录现有客户中台，从应用主页进入租洗相关模块，确认演示标识及当前场景。
2. 查看或维护一期允许的客户、服务、品项及配额信息；已有合成场景可直接作为起点，不要求先录入整套基础数据。
3. 查看有来源说明的期初资产与净品准备，创建或调整允许的需求和备货。
4. 进入物流作业视角，执行装车与交付；返回 PC 追溯并查看酒店查询结果，核对同一对象及数量。
5. 执行司机回收交接与工厂复核，区分观察、实收、差异及适用的配额结果。
6. 重置场景并重复演示，确认数据、单据关联和异常入口均能恢复。

| 场景 | 必须看到的结果 |
|---|---|
| 正常周转 | 操作前后数量、状态、关联单据与各端查询一致，保存实际生效，取消无变化 |
| 装 100、交 98、2 件待处理 | 区分需求、实装、实交与剩余去向；未完成部分不能被总状态掩盖，后续退回或补发按既有规则展示 |
| 司机交接 80、工厂实收 78 | 区分交接与实收证据、差异及后续处理；配额恢复按明确标识的候选策略展示，不重复恢复，不自动认定酒店赔偿 |
| 漏扫或重复扫描 | 已识别、有效、重复、异常数量清晰；重复事件不重复改变模拟库存、配额或单据结果 |
| 版本冲突 | 使用不透明版本值模拟冲突，保留用户输入，查看最新状态后重新确认，不能静默覆盖 |
| 操作结果未知 | 保留原操作及稳定标识，查询或恢复同一操作；不能另建动作冒充重试 |
| 打印或附属步骤失败 | 适用时单独展示业务结果与打印结果，避免打印失败被显示为业务整体回滚 |

优先复用[租洗算例](../业务/租洗/结构化数据/租洗算例.json)。待采纳规则只展示本轮必要的候选方案，并写明关联问题、PD、假设及影响；不建立通用规则引擎，不将演示参数登记为正式默认值。

## 九、本机预览与验证计划

### 访问交付

首批先检查本机现有服务、端口和账号可用性，确认客户中台既有登录能够完成，再交付从登录到应用主页及原型路径的访问步骤。沿用本地服务，不开放公网、不建立隧道、不引入外部部署。

当前客户中台使用 Vite，本机入口为 `http://127.0.0.1:5174`，应用主页路由为 `/applications`。实施阶段已复用现有本机服务完成受控身份桩下的浏览器验证；专用账号真实登录仍待安全使用方式，具体证据见执行记录。需要另行启动时可使用现有 Vite 的命令行参数限定本机监听，不为此修改环境文件：

```bash
pnpm --filter @frontend/customer-console exec vite --host 127.0.0.1 --port 5174
```

酒店 H5 依据当前 `pnpm dev:mobile:h5` 脚本核对实际启动与本机监听方式；具体端口、入口路径和共享状态方式在第一批固定。客户中台能打开不能代替酒店入口或跨端状态验证；截图和启动日志也不能替代实际交互。

### 工程检查

以下命令根据当前 `package.json` 登记。实施时按实际改动和仓库要求复核命令；已执行检查的退出码、用例数量、缓存／跳过项及证据见执行记录，不将局部检查作为全部范围完成的证明。

| 检查 | 命令或要求 |
|---|---|
| 前端统一检查 | 在 `yixi-web` 执行 `pnpm check`，包含架构、格式、类型、Lint 与单测 |
| 跨包改动 | 执行 `pnpm typecheck`、`pnpm lint`、`pnpm test`；新增依赖关系或公开出口时核对 `pnpm check:architecture` |
| 客户中台构建 | `pnpm --filter @frontend/customer-console build` |
| 移动 H5 构建 | 涉及酒店页面时执行 `pnpm --filter @frontend/mobile build:h5` |
| 路由和核心入口回归 | 按仓库约定执行 `pnpm smoke`，并实际执行原型核心链路的浏览器检查 |
| 规范文档检查 | 在 `yixi-spec` 执行 `python3 校验/检查文档.py` 和 `git diff --check` |

当前移动端 `smoke` 仅执行 `echo "mobile smoke pending"`，不能计为移动业务验证。相关单测脚本允许无测试文件通过，必须核对实际执行数量。`pnpm check` 不包含构建和浏览器冒烟；根脚本成功不证明每个端别都已验证。

### 浏览器验收清单

- 现有账号登录、应用主页进入模块、直接打开详情、返回、刷新及演示重置；浏览器会话缺失或退出后沿现有登录规则处理。
- 查询、常用与高级筛选、分页、列设置及允许的新增、编辑、保存、取消、重复点击；隐藏筛选条件不能被错误丢弃。
- 核心链跨端共享状态，正常、空态、失败、受限视角、部分完成、差异及追溯。
- 版本冲突保留输入并重新确认；结果未知查询或恢复原操作；重复操作不重复计数或改变资金结果。
- Network 对照已确认清单：现有登录与必要平台请求允许，租洗模拟业务、文件、导出或设备动作不能泄漏到真实服务；未模拟请求不能回退真实后端。
- Console 无未解释错误；日志、截图和证据不含账号密码、令牌、Cookie 或真实客户资料。
- PC 至少检查 1280px、1080px；移动和终端检查适用窄屏、触控布局、长文本、抽屉底部及滚动行为；与当前客户中台视觉基线对照。

验证结果使用 `PASS`、`FAIL`、`NOT_RUN`、`BLOCKED`、`NOT_APPLICABLE`，另外注明“文档检查／真实登录及平台请求／模拟业务／真实业务”。真实登录成功不代表租洗真实接口联调通过；模拟业务通过不改写正式 UAT。
