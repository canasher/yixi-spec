# 租洗业务规则、状态与数据变化说明

> 文档包版本：R1.1 · 设计评审版（2026-10-01）  
> 使用对象：产品、开发、测试、Codex  
> 产品方向：一期租洗；普洗仅预留，后续实施  
> 状态：目标设计，不是已上线说明；推荐规则须按任务采纳，不得假定商业条款已获批准  
> 阅读入口：[共用规范](README.md)；来源及冲突记录：[决策记录](决策记录.md)


## 1. 阅读约定

本文件是目标业务规则主版。每个BR先列来源，再列本版推荐落地方案；来源有冲突时保留PD指向。**以下“应/禁止”表达推荐方案被采纳后的约束，不表示原产品已经批准了所有细节。** 不依赖其他未定事项的技术不变量可先采纳；商业参数以06门槛为准。

固定原则：实物、需求、配额、费用和资金不是同一事实；日志不等于业务已生效；识别到标签不等于质量合格；页面完成不等于资金已结。默认规则集中在本文件，其他文档只引用编号。

## 2. 推荐状态分层

| 对象/维度 | 推荐状态/表示 | 不应混入 |
|---|---|---|
| Asset.lifecycle | REGISTERED / ACTIVE / SUSPENDED / SCRAPPED / RETIRED | 已支付、已备货 |
| Asset.hygiene | UNKNOWN / DIRTY / CLEAN | 客户责任和赔偿 |
| Asset.quality | NORMAL / HOLD / REWASH / REPAIR | HU状态 |
| Asset.activity/loss | CIRCULATING / IDLE；NORMAL / SUSPECTED / CONFIRMED | 现金是否退回 |
| Turnover | OUTBOUND / IN_USE / RETURNED / DISPOSED | 是否回购已付；quota_release单独标记 |
| RentalOrder.fulfillment | DRAFT / CONFIRMED / FULFILLING / COMPLETED / CANCELLED / CLOSED_WITH_DIFFERENCE | 支付/核准状态 |
| Shipment | CREATED / PICKING / READY / PART_LOADED / IN_TRANSIT / PART_DELIVERED / DELIVERED / RETURN_PENDING / CLOSED / CANCELLED | 上一轮收脏 |
| Payment | UNPAID / PART_PAID / PAID；退款另有净额与记录 | 运输步骤 |
| Review | PENDING / APPROVED / REJECTED | 是否真实实物已处理 |
| HandlingUnit | UNUSED / USED / UNTIED / EXCEPTION / CANCELLED | 实物洗涤次数 |
| Receiving | 有效事实记录+校正引用；扫描批次有处理状态 | 强行套普洗收货中状态 |
| Stocktake | CREATED / SCANNING / REVIEW / CONFIRMED / CLOSED / CANCELLED | 前端暂停/继续按钮 |

上述枚举为目标方案，实施时必须核对仓库已有状态和迁移兼容。普洗未来单独定义接收过程状态，不把租洗日汇总强行套成普洗实物收货单。

## 3. 关键动作的数据变化总表

推荐采用DRIVER_HANDOVER和DELIVERY_EVIDENCE，商业模式由批准配置选择。本表为BR摘要，冲突以规则卡为准。
| 动作 | 实物/库存 | 配额Q/T/R/O | 费用/资金 | 关键防重 |
|---|---|---|---|---|
| 订货确认 | 不移动、不预留具体实物 | R+需求量，Q不变 | 生成唯一费用；PREPAY要求足额付款，BILLING留应收 | order_confirm_id |
| 备货 | 锁定资产reserved；实际搬至待发另记移动 | R不再次增加 | 不重复收服务费 | order_line+asset有效占用 |
| 装车 | 实装移车，释放对应实物reserved | R−实装、O+实装 | 不再次全额扣费 | shipment_item_asset+LOAD |
| 实际交付 | 只实收移客户、解对应扎，hygiene UNKNOWN | O不变 | 短缺减项按批准处置生成 | shipment_asset+DELIVERY |
| 司机有效回收 | 客户→车，关本轮custody | 默认O−有效件数一次；严格策略待厂收 | 不自动重新收服务费 | turnover+RETURN |
| 返厂复核 | 车→脏区 | 默认不变；严格策略首次实收才释放 | 不重复收费 | asset+原轮checkpoint |
| B/C补漏 | 按可信当前位置确认，不倒退 | 只补原轮未释放部分 | 不伪造生产/资金 | 原turnover+RETURN |
| 处理/打扎 | 确认产出→净区；HU关系独立 | 无 | 特处按case费用；重打无新增费 | run+asset+attempt / HU request |
| 日汇总 | 无 | 无 | 不得再创建相同服务费 | 客户+业务日+revision |
| 报废/丢失结案 | 按实际位置或最后可信位置 | 仅批准disposition可结责任 | 赔偿单独规则执行 | case+asset+disposition |
| 盘点扫描/点数 | 只观察，确认调整另立记录 | 不直接变更 | 不直接赔偿 | session+generation+event |
| 取消/退回 | 未装释放；已装实际退回才搬库 | 保留需求退回O→R；取消需求仅结清对应占用 | 先批准减项，再按原分摊及剩余可退额退款 | return/disposition/payment来源 |

**来源输入：** U：先租洗后普洗；S1原期次；S4/S5旧范围。 **决策：** PD-016,PD-022。 **状态：** 本版推荐，采纳范围按06登记。

| 规则要素 | 推荐落地说明 |
|---|---|
| 前置条件 | 先建立企业默认参数，协议可覆盖明确白名单。未实现的选项不能仅通过写数据库开放。 |
| 生效动作/数据变化 | 本版仅RENTAL+RFID_PIECE作为一期正常业务入口。CUSTOMER_OWNED/QUANTITY保留契约并明确拒绝外部办理。确认单据固化适用policy_version；新配置不回写旧事实。 |

### BR-R002 服务、所有权、持有与库存池

**来源输入：** S2一（p1）；S5§4～7；本版推荐解耦。 **决策：** PD-001,PD-003,PD-012。 **状态：** 本版推荐，采纳范围按06登记。

| 规则要素 | 推荐落地说明 |
|---|---|
| 前置条件 | 资产所有者、品项、追踪模式明确；酒店服务协议有效且与池兼容。共享池需明确配置，不自动解锁专属或归属不明存量。 |
| 生效动作/数据变化 | ServiceMode在协议与单据；owner在资产/池；位置和custody记录当前持有，三者不互相覆盖。标准租洗可选择同所有者同SKU共享；绣标、专属合同及未来普洗使用专属池。 |
| 重复与并发 | 同一实物只有一个权威池；迁移时锁资产并校验预留、在途、所有权。 |
| 撤销/更正 | 更换合同可复用兼容池；不兼容须受控处置，不能删除重建资产或隐式转移产权。 |
| 算例 | 同一酒店床单租洗、台布普洗：一个客户，两类服务明细；台布不会进入工厂共享可发池。 |
| 灵活性与限制 | 一期不做复杂池配置平台。独立inventory_pool_id为本版推荐技术选择；SKU/owner/tracking不可原地变更已有池。 |

### BR-R003 可信身份与四端数据范围

**来源输入：** G1 AGENTS/IAM；S1客户重置密码与酒店H5；S5§3.3。 **决策：** PD-018,PD-021。 **状态：** 本版推荐，采纳范围按06登记。

| 规则要素 | 推荐落地说明 |
|---|---|
| 前置条件 | 内部人员通过现有Account/Employee/INITIAL准入；酒店外部principal须通过专门客户绑定；设备须受信任绑定。 |
| 生效动作/数据变化 | hotel_id是过滤/业务对象，不是授权证明。酒店每次请求、导出与文件读取求授权客户交集；注销、解绑、停用后缓存失效。重置密码通过统一身份能力一次性流程，不显示旧密码。 |
| 重复与并发 | 服务端重复请求重新校验当前准入；不能用幂等响应绕过已撤销身份。 |
| 撤销/更正 | 撤权不得删除历史业务操作者；异步作业重查授权或使用批准系统身份，二者不混用。 |
| 算例 | 酒店A账号篡改hotelId=B、订单ID、导出任务ID或fileId，均不能获取B数据。 |
| 灵活性与限制 | 外部身份接入是TASK-02专项门槛。不得把酒店用户伪造成工厂员工，也不另建密码表；现有Session链路需经IAM专项评审扩展。 |

### BR-R004 注册、激活与可发资格

**来源输入：** S2三；S3四及十，激活库位图文冲突。 **决策：** PD-019,PD-024。 **状态：** 本版推荐，采纳范围按06登记。

| 规则要素 | 推荐落地说明 |
|---|---|
| 前置条件 | 注册需有效SKU、明确所有者及唯一当前标签；未注册扫描不能直接当注册。 |
| 生效动作/数据变化 | 注册产生REGISTERED、NEW_INACTIVE位置和初始事件；激活只确认ACTIVE，不等同CLEAN。推荐默认DIRTY/HOLD待首次处理；可证明已合格的新净品通过授权初始放行进入CLEAN/NORMAL。 |
| 重复与并发 | 注册源行键及当前EPC唯一；重复设备读不增资产；并发碰撞整项拒绝。 |
| 撤销/更正 | 未进入运营可作废注册记录但保留标签历史；已运营只能换芯或退役，不物理删除履历。 |
| 算例 | 50件新布草注册后可查50件，但可发0；其中有洁净交付证明的20件经授权初始放行后可发20。 |
| 灵活性与限制 | 新净品直接放行需记录来源与操作人；不将“激活即脏/即净”解释成行业通用事实。 |

### BR-R008 本轮有效回收、保管与配额释放

**来源输入：** S2八；S3五/十二；推荐将多次扫描与有效回收分开。 **决策：** PD-005,PD-021,PD-023。 **状态：** 本版推荐，采纳范围按06登记。

| 规则要素 | 推荐落地说明 |
|---|---|
| 前置条件 | 找到资产当前未结租洗turnover，确认来源客户及实际交接；没有本轮来源不能猜测新的return。 |
| 生效动作/数据变化 | 推荐DRIVER_HANDOVER策略：有效司机交接关闭客户实物持有，移到车辆，并释放该轮outstanding一次。FACTORY_ACCEPT策略下司机只变保管，quota_release保持PENDING直到工厂实收。后续复核不能重复回收/释放。 有效“收脏”将hygiene置DIRTY，quality保留已有返洗/修补/隔离标记；未交付净品退回使用RETURN_UNDELIVERED，不冒充收脏，是否重新放行另行检查。 |
| 重复与并发 | 唯一turnover_id+RETURN；一轮最多一次净有效回收及一次净配额释放；换request_id无效。下一轮装车建立新turnover，允许同资产再次回收。 |
| 撤销/更正 | 确认错误用显式冲正且检查后续事件；已进入新轮禁止旧更正覆盖新位置或释放新轮配额。 |
| 算例 | 同40件司机收→返厂→打扎，有效回收40，不是120；默认配额只加40。 |
| 灵活性与限制 | 企业默认+协议覆盖确认节点；记录原规则快照。custody关闭与quota_release分开，保证严格工厂实收策略仍可表达。 |

### BR-R009 补漏、错位、陌生与多店归属

**来源输入：** S3十二；S2九计入/不计入；原A/B/C沿用展示。 **决策：** PD-005,PD-017。 **状态：** 本版推荐，采纳范围按06登记。

| 规则要素 | 推荐落地说明 |
|---|---|
| 前置条件 | 已注册资产、可信物理出现、明确未结轮次/责任客户和允许工位；无证据不得用请求hotelId补归属。 |
| 生效动作/数据变化 | A正常/B返厂补漏/C工作台补漏映射来源；B有充分证据可自动确认，C默认人工确认。多店按原责任客户分记录；现场交货客户可不同但需异常证据。未知/报废/归属冲突保留观察与异常，不进入正常计数。 |

### BR-R010 租洗日汇总、业务日和更正

**来源输入：** S2六1.3/1.4；S3十二；图文未区分汇总更新点。 **决策：** PD-025。 **状态：** 本版推荐，采纳范围按06登记。

## 5. 配额与库存完整算例（推荐口径）

Q=合同配额，T=有效临时增配，R=订单未发预占，O=已发未回/待回收确认占用。A展示可为负，但新单允许量取max(0,A)，不抹去超配额事实。

| 步骤 | Q | T | R | O | A=Q+T-R-O | 库存事实 |
|---|---:|---:|---:|---:|---:|---|
| 初始 | 200 | 0 | 30 | 120 | 50 | 工厂有待备货，酒店/送出在途120 |
| 司机确认回40 | 200 | 0 | 30 | 80 | 90 | 40在回程车辆，不是工厂净品 |
| 工厂复核40 | 200 | 0 | 30 | 80 | 90 | 40到脏区，不再释放 |
| 原预占30实际装车 | 200 | 0 | 0 | 110 | 90 | 30送出在途，R转O |
| 新订单预占10 | 200 | 0 | 10 | 110 | 80 | 不占用指定实物 |
| 取消未发新订单 | 200 | 0 | 0 | 110 | 90 | 无真实实物回仓动作 |

A不是可发净品数。即使A=90，也可能可发净品只有20；反之工厂有100件净品，不代表客户可超额下单100。

### 5.1 未交付差异、补发与取消（R1.1）

差异明细必须有原订单行、原装载/turnover、资产集合、处置数量、`disposition_id`、版本和规则快照。默认`KEEP_DEMAND`保留原履约义务；`CANCEL_REMAINDER`为批准取消。去向未知或仅申请退回时保留原O，不凭“欠送”先恢复R；一期须实际退回或批准责任结清后才能对该部分补发。先补发再追责的垫货策略不在一期默认入口，未来必须有独立有界增配和风险占用，不能关闭守恒校验。

| 动作 | 配额与原需求 | 费用/实物 |
|---|---|---|
| KEEP_DEMAND：原未交付实物退回/批准责任结清n件 | 同事务O−n、R+n；原在途需求转待补发，A不变 | 退回按真实位置；责任处置不伪造回厂；原费用不减、不新增服务费 |
| 对恢复的需求补发n件 | 新履约批次R−n、O+n；仅实交才计完成 | 沿原订单价格；新turnover关联原差异，旧装载/退回保留 |
| CANCEL_REMAINDER：取消未装或已恢复预占n件 | R−n；批准取消量+n | 释放实物预留，批准费用减项后按资金规则处理 |
| CANCEL_REMAINDER：取消仍在途n件 | 取消意向先记录；实际退回/批准责任结清才O−n，不恢复R | 费用及责任按处置依据分别处理，不因头状态直接退款 |

例：本订单100件全部装车，实交98，2件退回继续补发。原订单R0/O100→退回R2/O98→补装R0/O100，确认实交后累计履约100；没有第二笔全额服务费。这里O为本订单相关轮次贡献，账户总O仍包括其他未回资产。恢复R是原占用转换，即使Q调低或T过期导致A<0，也不重新抢新额度、不免除负额；超原差异数量属于新需求，须重新检查额度。

履约守恒按订单行检查：确认需求D=已批准取消C+累计有效交付F+未决在途I+待发预占R；客户后续正常收脏不减少F。退回补发使I→R，取消使I或R→C，补发最终R→I→F；历史累计装载可超过D，不能用累计扫描/装载量代替有效履约分配。未交付实物一旦原处置结清，不再占I；未知去向未结清仍占I。

O→R、原轮关闭、有效分配失效与补发需求恢复在同一企业事务内提交；唯一`原差异明细+处置序号`并限制累计处置不超未决量。取消与补发锁同一订单行/差异版本：取消先提交则补装拒绝；补装先提交则取消转新批次退回流程。对相同资产再次装载使用新履约批次和新turnover，不覆盖原装载键。恢复R不等于预留已退资产，退回净品须重新验质才能备货。

## 6. 金额与退款的固定算例

测试价2.00/件，订50总100，实交48且批准减免2 => 原费用100 + 减项−4 = 净96。只部分交付、尚需补2时不可提前退款4并同时又按原费用补货，须按处置单决定。

假设规则允许赠送先用，洗涤130分摊为赠送20、现金100、信用10；信用未偿时按原剩余分摊比例退13：赠送2、现金10、信用已用减少1，净分摊剩18/90/9。算法以整数分计算，按可退的原剩余分摊权重向下分配，再按GIFT、CASH、CREDIT固定顺序补余分且不超各路剩余额；重复分配以已冻结结果为准。分次舍入可不同于一次合退，但累计各路不超原额，全退时各路余额归零。其他顺序须新版本，不能不同端各算一套。

商业参数是规则配置而非测试夹具。价格2.00、赔偿80、比例25和阈值n天均不是系统默认报价或赔偿承诺。真实配置未采纳时，测试可验证计算器，但真实扣退禁用。

### 6.1 退款资格、限额和在退占用（R1.1）

先由取消/减价/回购等合法来源形成批准调整及可退权益，再申请退款；有付款不等于可以任意退。以下量同客户、币种、费用及原支付分摊计算，金额均为非负整数分：

- P：原成功结算分摊总额，包括现金、合格赠送和信用结算；信用结算不等于实收现金，后续偿还信用不再次增加P。
- F：已成功退回/解除的结算分摊总额；H：PENDING/PROCESSING/UNKNOWN等尚未确定终态的在退预留。失败只有确认没有退款效果后才能释放H，超时不能直接释放。
- Ls：本次批准调整来源s分配到“已结算部分”的可退总额；Fs、Hs为该来源已退与在退。应收冲减不占用L，也不冒充退款。
- 本次金额x必须满足`0 < x ≤ min(P−F−H, Ls−Fs−Hs)`；各原分摊同时满足`Fi+Hi+xi ≤ Pi`。0额减免可留决策记录，不创建0额支付事务。

始终校验`F+H≤P`、`Fs+Hs≤Ls`及各路非负。累计退款上限是P，不能再与已经扣过退款的净支付P−F比较。例：付100、批准退100，先退60再退40合法，第三次再退0.01拒绝；已退60且在退40时，换请求号也不能再申请。新增支付不会自动增加某张旧调整的Ls；新减免必须另有合法来源。

一期内部钱包退款在单个企业事务完成批准额度消费、原分摊退回和账户/流水，不产生可被重复消费的中间余额。未来外部渠道用先冻结H→通道执行→确定成功转F/确定失败释放H；结果未知保留H，查询原事务恢复，不新建退款逃避在退占用。每笔可退权益和原支付分摊共享锁，业务退款来源唯一，不能只对requestId去重。

GIFT回原赠送桶并保留用途限制；CASH回原现金钱包。若未来存在外部现金渠道，按原通道/明确授权的钱包替代策略办理。退款不直接改变配额和实物；已批准减项、待退款与到账金额按financing_state互斥统计，不重复提高可用资金。

### 6.2 信用已偿还后的退款与还款竞争（R1.1）

信用必须落实到原`credit_draw_allocation`，每次还款落实到`repayment_allocation`及真实资金来源。不能用客户整体credit_used或其他订单的还款推断某笔债务已偿。设原信用结算额Pc、已分摊还款S、此前退款冲掉的未偿本金W、此前退回的已偿款T，则原笔未偿`d=Pc−S−W≥0`，已偿尚可返还`s=S−T≥0`。

对本次分到信用路线的退款x，先按§6.1检查原路额度。设已有在退的债务解除预留Hd、已偿返款预留Hs，则`d_available=d−Hd≥0`、`s_available=s−Hs≥0`；冻结去向为`debt_release=min(x,d_available)`、`repaid_return=x−debt_release≤s_available`，两部分再进入本次预留或原子成功。前者成功时减少原笔债务及汇总credit_used，后者成功时退原还款来源；两者之和才是本次信用退款，不重复记两笔退款。成功更新W和T并解除对应预留，S保持原还款历史；赠送不得成为信用还款来源。

| 原信用额 | 已还S | 本次退x | 冲原未偿 | 返已偿款 | 结果 |
|---:|---:|---:|---:|---:|---|
| 50 | 0 | 20 | 20 | 0 | 原笔未偿30 |
| 50 | 50 | 20 | 0 | 20 | 未偿仍0；原还款现金返20，不生成负credit_used |
| 50 | 20 | 40 | 30 | 10 | 未偿0，保留已偿10，对应原服务保留净额10 |

多次现金钱包还款按已冻结还款分摊的时间、ID顺序返还，逐笔限制`返还+在退≤原还款分摊`。经核验的线下还款一期可返同客户现金钱包，明确标记`CASH_WALLET`，不声称钱已退到银行卡；退外部银行为后续独立支付/凭证流程。不得把返还款自动抵扣其他债务或变成赠送。

还款与退款按同一原信用分摊串行校验。已预留债务解除的部分不再接受还款；已预留返已偿款的部分不再可退。内部还款发现原债务已结清则整笔拒绝/回滚，不能先扣现金后丢余额；退款和还款无论谁先提交，最终原债务非负且实际净资金一致。已到账但未能核销的未来外部还款需独立暂收处理，不能伪造成功核销。

### 6.3 部分支付赔偿的减免与回购（R1.1）

先验证找回资格、实物/责任证据及合同快照，单纯扫到标签只形成候选。对原comp_line在同一事务锁定费用和支付分摊后冻结：B=本次找回处置前有效应赔额（扣已有普通调整，不包含本次减免）；N=已成功结算−已成功退款；U=B−N为未付额。已有未决调整/在退退款或N>B时先对账完成，不对不一致状态自动结案。

新规则推荐`ASSESSED_AMOUNT_PERCENT`：V=按分HALF_UP(B×r/100)，0≤V≤B；`offset_unpaid=min(V,U)`，`refund_entitlement=V−offset_unpaid`。追加贷项总额V，分别冲未付应收和生成可退权益；权益经§6.1/6.2结算。先定V、再分去向，同一B/r不会因客户早付或晚付而改变净责任B−V。

| B | 已结算N | r | 减免V | 冲未付 | 可退权益 | 余欠 |
|---:|---:|---:|---:|---:|---:|---:|
| 80 | 0 | 25% | 20 | 20 | 0 | 60 |
| 80 | 30 | 25% | 20 | 20 | 0 | 30 |
| 80 | 70 | 25% | 20 | 10 | 10 | 0 |
| 80 | 80 | 25% | 20 | 0 | 20 | 0 |
| 80 | 30 | 100% | 80 | 50 | 30 | 0 |
| 80 | 30 | 0% | 0 | 0 | 0 | 50 |

如果合同规定找回即全额免赔，应批准全额减免（r=100）；不能看到“未支付”就擅自免除全部责任。如果N包含信用结算，可退权益中的信用部分先冲该笔信用债务、再退已偿款，因此上表“可退”不一定都是现金。

兼容旧`PAID_AMOUNT_PERCENT`时必须显式快照：V=U+round(N×r/100)，冲U、退round(N×r/100)，该策略确实随支付进度变化；仅用于明确采纳的旧条款，新单默认推荐前者，未实现的策略拒绝。不迁移旧比例到新基数，不因r调大就重跑已结回购。减免凭证、分配、退款权益与规则快照同事务，退款执行可恢复；同案同资产只有一个原始找回处置，更正另有版本和批准差额。

## 7. 错误、失败和展示约定

业务拒绝必须返回稳定code、中文message、requestId及允许展示的明细，不能暴露其他企业ID、数据库地址或密钥。基础建议错误：SCOPE_FORBIDDEN、ASSET_STATE_CONFLICT、UNKNOWN_TAG、IDEMPOTENCY_CONFLICT、ALREADY_APPLIED、QUOTA_INSUFFICIENT、PAYMENT_REQUIRED、PRICE_MISSING、POLICY_NOT_ACTIVATED、STALE_EVENT、VERSION_CONFLICT。具体HTTP/ApiResult数值码沿当前仓库规范登记，不能复用既有文件40901含义。

单据一组需要守恒的命令全成功/全回滚；可独立处理的设备批次逐项提交，成功结果可查询。流程推进成功但通知/打印失败不重做库存。外部附件保护/确认属于既有跨库恢复协议，不能把其失败隐藏成业务凭证已完整绑定。
