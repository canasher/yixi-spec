## 2. 用户、边界与身份

企业一个独立业务库，V1仅canonical INITIAL。多酒店不等于多工厂。内部管理员、财务、生产、仓管、司机复用已有IAM；业务职责不是要求创建第二套角色系统。酒店外部用户绑定允许客户，不套企业员工准入；设备独立可信主体。Account是身份，资金账户是业务余额，客户资料不是密码表。

酒店一期以原列示查询为主；司机送达可采用带交接证据的完成策略，不能假冒酒店签名。需要酒店签收按钮、自动下单或更多来源时按范围变更启用，不把资料截图当一期页面清单。

## 3. 业务主流程

```text
客户/品项/服务及价格配置 → 资产注册/激活/期初 → 工作台处理结果确认 → 打扎
                                                  ↓
工厂代录需求（推荐最小依赖） → 配额与资金检查 → 备货 → 装车 → 交付确认/差异处置
                                                                       ↓
下一轮：司机收脏 → 工厂复核/补漏 → 返洗/特洗/报废或放行 → 打扎 → 再供应

有效回收记录 → 按业务日汇总收货单 → 查询/日报/月报（汇总不重复入库）
费用事件 → 账单核准/支付或退款 → 客户资金流水（不从单据展示状态直接推导款项）
```

首单从有证据的期初净品开始，不要求先收回脏品。后续回收不阻塞上一张已完成净品订单；未交付差异则继续关联原需求或批准的减免。一次车程可含送和收两种动作，但实发、实收及责任独立，不用净差替代。

完整Route和工序管理按原PC生产三期边界后续设计。本期“生产”仅含原一期终端功能及必要的处理确认，不宣称自动验证了消毒质量或机器完工。

## 4. 本期必须可完成的实际工作

### 4.1 客户上线与初始经营

实施人员配置客户、服务品项、归属/兼容池、配额、价格及费用类型；初始化实际资产、酒店持有和资金需预览与授权确认。不能将配额当库存、把已在客户处的资产默认为工厂可发、或凭导入给客户制造收费。

### 4.2 收货与打扎

司机可按单店或多店收脏；无人收脏设备上传先保存观察，后形成有效业务结果。工厂复核不重复客户回收；B/C补漏显示原因和原轮次。未知标签/错位布草进入异常，不为“完成一单”随意造客户。工作台“产出确认”与“仅重新打扎”操作语义清楚，重印失败不重新洗一次。

### 4.3 订货、备货、发货及取消

一期发货列表需要稳定来源，推荐工厂最小代录作为依赖而非新增酒店下单。锁单后改单需显示对实物、配额和款项的影响。备货、装车、交接数量分别展示；部分差异可保留未决，不直接全量完成。运输中取消显示“取消申请/待退回”，而非给用户误导“已回仓”。

未交付差异默认保留原需求：实际退回/批准责任结清后恢复原预占，补发关联原单、沿原价且不重复收费；取消剩余需求为另一种明确处置。界面显示待退、待补发、已补发和批准减免数量，客户正常收脏不会重新打开已完成的原需求。规则见02§5.1。

### 4.4 特殊处理与盘点

PC和物流提报特洗、返洗、重污/破损责任；一期PC补必要受控处理完成入口，生产特洗快捷页仍二期。生产报废及PC查询一期，物流报废按钮二期。盘点先出差异再确认，普通点数不改库存；扫描期间合法移动必须可识别。

### 4.5 财务与客户查询

R1.1资金补充：支持批准额度内分次退款，已退及在退共同占用原支付限额。信用退款按原笔债务区分未偿与已偿款；已偿部分按原还款来源返还。赔偿找回先按合同确定减免额，再冲未付、退已结算，页面分别展示减免、冲欠款、返信用及退现金金额，不把全部“回购金额”显示为现金到账。规则见02§6.1～6.3。

客户报价/特殊价格、账单、账户、充值审核和资金记录进入一期。推荐先做线下凭证充值与企业内部子账；“实时钱包支付”不等于接入微信/支付宝。自动赔偿回购保留原S1 G22要求，但算法、价格和启用授权缺失时不执行真实扣退。客户H5展示允许客户的库存/配额、单据、价格、账单、资金及日报月报；金额与可用配额不能被前端缓存当权威。

### 7.1 共用交互与四端边界

PC列表统一提供原清单声明的筛选、自定义列、导出、详情等；不擅自给每个空白功能扩充全部CRUD。长任务展示处理状态和失败明细，不能只用Toast宣称成功。高风险编辑弹窗展示原值、影响与原因；已核准账单使用更正而非原地覆盖。

生产端以扫描会话为中心，先显示已识别、有效、重复、异常数量，再确认实际业务。打印状态与业务状态分开。物流端先选择被授权任务/客户/车辆，支持明确“单店/多店”；中断可用原requestId查询结果。酒店H5只读默认，页面的加载失败、权限失效和统计延迟明确展示，不能用空库存代替接口错误。

版本更新需批准发布源和完整性校验；芯片同步必须有权限范围和撤销墓碑；退出登录清理当前身份令牌与敏感缓存，但不得把甲用户的待提交业务悄悄转给乙用户。

列表、详情和关联查询使用同一对象身份与字段口径。返回列表保留本次筛选和页码；数据为空、读取失败、权限失效分别提示。业务日期、实际发生时间和系统记录时间标明含义及业务时区；可用配额、资金和提交资格由服务端重新校验，展示值不构成占用承诺。

所有关联跳转、附件和导出重新执行现有对象范围与字段授权。无权查看时给出受限提示，不通过链接、对象编号或自定义列泄漏其他客户内容。操作前展示本次对象、数量/金额、处置原因及影响；提交后以服务端结果更新数量、金额和状态。版本冲突提示刷新并重新确认；结果未知提供原操作查询/恢复，不诱导用户另建同一退款或交付动作。

业务日志以时间线或列表展示业务动作、操作者/设备、发生/记录时间、变更前后状态及数量/金额、原因、关联原单与更正记录。成功事实和失败尝试分开展示；打印/通知失败不显示为业务回滚。产品页面不暴露凭据、原始请求体或无关技术日志，受限诊断信息只供有权限人员查看。
