# 结构化追踪与合成算例

这些JSON与[共用规范](../共用规范/README.md)配套，业务描述以Markdown主版及采纳记录为准。当前七份数据保持原R1.1内容和编号不变；英文键名是已有数据契约，文件名统一改成中文。

| 文件 | 用途与主版 |
|---|---|
| [需求索引](需求索引.json) | 25个FR；关联规则、任务及UAT，对应产品需求 |
| [规则索引](规则索引.json) | 32个BR；来源、PD、前置、变化、重试、更正及算例，对应业务规则卡 |
| [任务索引](任务索引.json) | 23个TASK；依赖、FR/BR/UAT、交付、不做范围、门槛和验证，对应实施任务卡 |
| [验收索引](验收索引.json) | 70个UAT；数据、步骤、预期、BR、类型、门槛和状态，对应用例卡 |
| [决策索引](决策索引.json) | 38个PD；推荐结论、来源、影响和采纳门槛；实际采纳记录另在决策主版 |
| [范围追踪](范围追踪.json) | 123个原功能组，保留原行号、单元格、期次、动作、备注及FR/BR/TASK/UAT |
| [租洗算例](租洗算例.json) | 合成资产及数量/金额示例，包括24组R1.1数值场景，不含真实业务数据 |

从FR查规则与任务，再按TASK的`deps`找到依赖，从UAT的`br`和需求索引反查来源。TASK-21的“所有一期任务”为总验收汇总语义；TASK-18随业务切片交付，不能生成反向循环依赖。

维护顺序及状态定义见[文档维护约定](../../../协作指南/文档维护约定.md)。变更对应字段时同步主版；仅修改JSON使检查通过不能替代规则评审。校验命令在仓库根目录执行 `python3 校验/检查文档.py`，不需要额外依赖。
